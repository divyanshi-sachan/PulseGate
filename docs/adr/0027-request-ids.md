# ADR-0027: The gateway always generates its own request IDs

- **Status:** Accepted
- **Date:** 2026-10-23
- **Source:** OPEN_QUESTIONS Q17; system_design §8 (`GatewayRequestContext.requestId`); tech_impl §9.1
- **Relates to:** ADR-0011 (errors carry `requestId`), ADR-0021 (header forwarding)

## Decision
- Every request gets a new ID, `req_<uuid v4>`, generated by the gateway (Fastify `genReqId`, `requestIdHeader: false`).
- An incoming `X-Request-ID` is **discarded**: it is never reused, logged or forwarded.
- The ID is sent upstream as `X-Request-ID`, returned to the client as `X-Request-ID` (overriding any upstream value),
  included in every normalized error body, and attached to every log line for that request as `requestId`.
- Requests rejected at the socket level (upgrade/CONNECT, ADR-0023) get an ID too.

## Alternatives considered
- **Also log a validated client ID** — helps client correlation, but adds a second ID to reason about. Can be added later.
- **Reuse the ID from trusted proxies** — useful behind a load balancer; revisit if a deployment needs one ID end to end.

## Consequences
- Clients can't forge IDs or inject junk into logs through this header.
- Tests: the response ID has the `req_` format, matches what the upstream received, and differs from a client-supplied value.
